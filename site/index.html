From first frame to hand-off.

The workflow designers already know, in a tool your team runs itself. Pick a step.

Step 1 of 5

Lay out screens

Draw frames for each screen, then let auto layout do the spacing. Cards hug their content, lists fill their parent, and colours come from variables so light and dark modes stay in sync.

  • Frames, auto layout, constraints and grids
  • Colour, number and text variables with modes
  • Text, images, effects and background blur

Step 2 of 5

Build the design system

Turn repeated pieces into components, combine them into variant sets, and share them from the Assets panel. Change the main component and every instance follows.

  • Components, instances and overrides
  • Variants with properties such as Style and State
  • Libraries shared across documents

Step 3 of 5

Make it clickable

Connect screens with interactions, pick the transition, and present the flow to check it feels right before anyone writes code.

  • On click, hover and drag interactions
  • Navigate, overlay and scroll-to actions
  • Present mode for walkthroughs

Step 4 of 5

Review together

Share a link. Everyone sees each other's named cursors and edits live, can follow a presenter, and leaves comments right on the canvas.

  • Live cursors, selections and edits
  • Spotlight and follow a presenter
  • Comments pinned to the design

Step 5 of 5

Hand off to developers

Dev Mode shows measurements, annotations and generated code, with component properties turned into props, and exports assets in the formats developers need.

  • Inspect spacing, sizes and styles
  • Generated React and CSS for components
  • Export PNG, SVG and PDF

Your designs are company assets. Most design tools keep them in someone else's cloud.

FigCraft Cloud is for product and design teams that want real-time collaboration they can run and own, for companies that need single sign-on, tenancy and control over where data lives, and for platforms that want a design editor inside their own product.

The lock-in

Your source of truth sits in a format and a cloud you do not control, on terms that can change.

The bill

Pricing grows with every seat

Reviewers, engineers and stakeholders all need access, and each one costs more.

The region

No say over where data lives

Self-hosting is rarely an option, so residency and retention are someone else's decision.

Design together, live.

Share a link or sign in, and everyone in the document sees each other's cursors and edits as they happen. It runs FigCraft's own collaboration protocol: one server order, per-property last-writer-wins and undo that only takes back your own changes.

  • Real-time presence. Cursors, selections and avatars move live.
  • Per-person undo. Your undo never removes a teammate's work.
  • Viewer and editor links. Expiring, revocable, stored only as hashes.

Never lose a confirmed edit.

The relay writes each batch of edits to PostgreSQL before it confirms or broadcasts it. If a server dies mid-edit, nobody was told the edit happened, so nobody loses it.

Self-host in minutes.

You need Docker with Compose, and about 8 GB of free RAM and 20 GB of disk for the first image build.

  1. Clone the repositoryEverything, including the Compose stack, lives in one repo.
  2. Create the secret filesThe stack reads secrets from files; deploy/saas/README.md lists them.
  3. Start the stack and make a linkOpen the printed http://127.0.0.1:8080/edit/#join=… link in two tabs and co-edit.

Walk through the demo

bash
$ git clone https://github.com/schnsrw/figcraft.git
$ cd figcraft
# Create the secret files the stack expects (see deploy/saas/README.md), then:
$ docker compose --env-file deploy/saas/env.example -f deploy/saas/compose.yaml up --build -d
# Create a document and print a link that opens it in the browser editor:
$ docker compose -f deploy/saas/compose.yaml exec cloud figcraft-cloud --create-share-link

Questions, answered honestly.

Is it ready for production?

Not yet. FigCraft Cloud is an early alpha. Browser co-editing on the cloud stack works end to end, and identity, tenancy and authorization are complete with their test gates passing.

Embedding in other products (host registration and token validation exist; the host API and browser integration are in progress), the desktop and browser cloud clients, AI features and production operations (billing, observability, restore drills) are on the roadmap and not finished. Try it, but don't put irreplaceable work in it yet.

The roadmap percentage counts tasks, not readiness. The remaining relay, recovery and operations work is the hardest and riskiest part, so read it as "how much is built", not "how close to production". The maturity table shows where each area stands.

How does it relate to FigCraft?

FigCraft Cloud is an independent fork of FigCraft, the open-source Rust design editor. It keeps FigCraft's editor, renderer and command model unchanged, adds the cloud platform in separate crates, and merges upstream regularly so editor improvements keep flowing in. Read why the fork exists.

Can I run it on my own servers?

Yes, that is the point. The whole stack is one Docker Compose file: the cloud service, PostgreSQL, Redis, SeaweedFS or any S3-compatible store, the web editor and a Caddy gateway. Production settings, backups and upgrades are covered in deployment and operations.

What's the licence?

Code and original assets are dual-licensed under MIT or Apache-2.0, at your option. There is no paid edition and no licence key.

What's next?

Closing out the distributed relay (large images through the asset channel and the full gate run), then host APIs and webhooks for embedding, the browser workspace and desktop cloud documents, an AI gateway, and production operations. See the live roadmap.
