What's next.

The distributed relay is built and tested against a real database; the remaining work is closing it out, then the clients.

Built and tested for S5: room leases with renewal, loss and release; any relay passing a client on to the room's owner; graceful drain for rolling releases; warm idle rooms and scheduled snapshots; bounded quotas; durable client ids; and tests that kill the real process before and after a commit. Rooms of different documents now commit at the same time, measured at about a thousand commits per second per relay.

  • Large images through the asset channel: verified references instead of inline bytes, which needs editor support as well as the relay.
  • The S5 gate: one full run of the multi-replica, crash, revocation, compatibility and load tests with no acknowledged edit lost.
  • Embedding for host products: registration, keys and token validation exist; the host API, webhooks and browser integration follow.
  • Browser workspace and desktop cloud documents: open, edit, reconnect and export one cloud document from both.
